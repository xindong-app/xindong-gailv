# 数据更新流程

> 当前 `dataVersion`：`2026.08.14.3`
> 当前 `modelVersion`：`4.0.0`

本流程用于更新 [`app/src/data/evidence-registry.json`](../app/src/data/evidence-registry.json)、[`app/src/data/population-by-age.json`](../app/src/data/population-by-age.json)、[`app/src/data/city-population-sources.json`](../app/src/data/city-population-sources.json)、[`app/src/data/cities.ts`](../app/src/data/cities.ts)、[`app/src/data/population-policy.ts`](../app/src/data/population-policy.ts)、[`app/src/data/relationship.ts`](../app/src/data/relationship.ts) 及模型参数。目标不是“换个年份”，而是保证来源、分母、转换、量化准入、相关性、测试和页面说明一起更新。

## 0. 先过人口量化准入门槛

证据登记与主人口准入是两层检查：

1. `evidence-registry.json` 记录来源到底观察了什么、分母是什么、可作直接值/锚点/校准还是必须排除。
2. `population-policy.ts` 决定该产品维度能否真正削减主人口。只有 `included_estimate + apply` 可以进入；`unquantified` 输出上界；`research_only` 只能进入另行标注的研究情景。
3. 未登记的维度ID必须 fail closed 为 `unquantified`，禁止凭常量或旧代码自动进入连乘。
4. 收入、资产、住房、车辆在取得同口径的18—50岁个人联合分布前，固定为 `research_only/do_not_apply`。
5. `scenarioMethod` 必须描述引擎实际消费的范围传播方法；只有倍数法才允许登记 `scenarioRange`。身高参数端点、饮酒 raking 端点不得伪装成通用 0.70—1.30 倍数。
6. 学历当前例外地具备主人口准入：`education.level` 必须保持 `included_estimate/apply/estimate`，方法锁定为 `education_age_sex_direct`。任何更新都必须继续证明专科、本科、硕士、博士四类互斥，且本科不自动包含硕博。

完整证据与浏览器展示数据分离：`evidence-registry.json` 是唯一权威全量登记，`evidence-validation.ts` 只供脚本/测试做严格校验；浏览器只加载由其生成的 `evidence-runtime.json` 可追溯投影。每次修改全量登记后必须运行 `npm run generate:evidence-runtime`，随后 `npm run validate:model` 会逐字段比对并拒绝陈旧投影。这样不会为了前端徽章把全部方法正文和 Zod 校验器打入生产包。

学历表采用相同边界：`education-by-age.json` 是包含来源元数据、SHA-256、总计、完整五岁组校验和全部原始计数格的权威/审计表；生产 `education.ts` 只加载紧凑 `education-runtime.json`。修改权威表后必须运行 `npm run generate:education-runtime`（脚本为 `scripts/generate-education-runtime.ts`），再运行 `npm run validate:model`。门禁会逐格比对权威表与投影，拒绝陈旧投影；不得手工维护投影或让生产代码直接加载全量审计JSON。

关系情境层使用独立的低可信来源登记与版本，因为它不属于主人口证据、也不能回写主人口。修改 `relationship.ts` 时必须同步关系情境版本、数据版本、检索日、默认三点范围和方法文档。`validate:model` 同一发布入口会检查：研究来源 HTTPS、分析者情境仓库相对路径、未来日期、来源 ID 引用、默认范围有序且位于 0—1，以及输出版本是否与登记一致。

全条件综合情境同样与可靠人口准入分层：[`dimension-probability-registry.json`](../app/src/data/dimension-probability-registry.json) 是69维完整审计源，记录依据类型、来源ID、三点情境、17个相关组、方法、转换参数、证据目录版本和局限；生产只加载紧凑 `dimension-probability-runtime.json`。学历是互斥分层母集，院校和收入在学历单元内条件化，不把学历再作为普通相关概率扣减。修改审计源后必须运行：

```bash
npm run generate:dimension-probability-runtime
npm run validate:model
```

门禁必须逐一证明69维无遗漏、8个可靠层维度不重复扣减、61个非直接维度均可产生有序概率、48个最大熵项明确为D/NA及分析者先验、依据类型说明完整、来源ID存在、证据目录版本绑定、星座日数守恒、学历/房车类别并集单调、收入/资产阈值单调、完整审计源与紧凑投影完全同步。当前60个情境政策含显式分析者先验；运行结果还必须把实际启用的相关强度情景计入 `assumptionCount`。D/NA可以缩小“全条件综合情境”，但仍不得改变或冒充可靠人口层。

### 城市新增/更新规则

- 只接受统计局、国家统计局调查队或政府门户承载的一手原始公报/人口发布页；搜索摘要、媒体报道、地产报告和百科不能落主估算。
- 权威维护链固定为 `city-population-sources.json` → `npm run generate:city-data` → `city-runtime.json` + `evidence-registry.json` 城市条目。完整来源、短值和局限只在权威源表维护；运行投影和证据条目不得手工各改一份。
- 必须同时登记：`mainEstimateStatus`、口径、年份、值、来源URL、证据ID、检索日和局限；名单版本与商业榜单原图哈希另由 `city-tier-roster.json` 固定。
- 城市公报没有18—50岁逐岁×性别结构时，基础池只可用“城市常住人口×2020全国详细表相应年龄性别份额”，固定分母为A0301/A0401详细表同口径的 `1,409,778,724` 人（`140,977.8724`万人），并使用0.70—1.30宽情景倍数；明确这不是置信区间。不得使用含另表200万现役军人的七普公报总数，也不得使用2025全国总量替换该分母。
- 数据回退顺序必须是：本市最新官方值 → 本市上一年官方值 → 同类城市代理情景。前两层都必须是本市一手常住人口数据，并明确记录时点差。
- “同类城市代理情景”只允许在未来确实缺少本市官方锚点时单独评审；必须列明参照城市，并从经济规模、区域、人口体量和迁移特征解释可比性。代理输出只能是低等级宽范围，必须逐处标注“同类城市代理情景”，不得落成或展示为本市官方点值。当前56城均有本市官方锚点，代理层未启用。
- 在代理情景尚未完成登记、实现与门禁前，缺少本市锚点的未知/未来外部城市保持 `unsupported/unquantified`。混选时不能只计算支持城市后冒充全部所选城市；应返回不支持城市清单并把总结果标为不可量化/部分上界，禁用占位值不得解释成0人。

- 统计分类、诊断标准或行政区划发生变化。
- 新数据使典型场景结果变化超过20%，或使结论等级改变。

## 2. 来源优先级

按以下顺序搜索和收录：

1. 国家统计局机器表、人口普查/抽样调查、主管部门行政数据。
2. 国家卫健委、中国疾控中心、教育部、民政部、人民银行等原始发布。
3. 同行评议系统综述、Meta分析和全国代表性研究。
4. 研究机构/行业报告，仅在官方与论文不足时交叉校验。
5. 透明模型假设；必须是C或D级，不能用来源机构名包装成官方参数。

技术/统计方法只引用官方文档、标准或原始论文。避免营销号、新闻二次概括、无作者转载。若原文确实只有付费期刊或主管机构官网无持久全文，登记原始书目信息，并说明当前URL是索引还是转载。

## 3. 一条证据的完整更新步骤

### 步骤1：先冻结旧版本

- 记录旧 `dataVersion`、`modelVersion` 和Git提交。
- 运行黄金场景并保存结果，包括基础池、逐因子变化、情景范围和置信等级。
- 不直接覆盖旧结果后再尝试回忆差异。

### 步骤1.1：同步浏览器证据投影

```bash
npm run generate:evidence-runtime
```

生成文件不得人工维护；`validate:model` 必须证明它与全量登记逐项一致。

### 步骤2：下载或定位原始表

记录：

- 发布机构与原始标题。
- 数据年度和发布日期。
- 真实持久URL，不记录搜索结果页。
- 表号、页码、工作表名或API查询参数。
- 检索日期（ISO `YYYY-MM-DD`）。
- 统计总体、样本量、权重、分母、单位、地域、年龄、性别和排除项。

对图片表/PDF表保留提取脚本或人工双录校验，不只复制一个汇总值。

### 步骤3：先判定产品定义是否匹配

逐项回答：

- 用户选项究竟是什么？例如“现在不吸烟”还是“从不吸烟”？
- 来源的分母是人、家庭、户均、单位就业者、全部居民还是登记事件？
- 来源给的是存量、年度流量、均值、中位数、率还是拥有量？
- 是否覆盖目标年龄18—50、目标性别与地区？
- 指标是否适合做硬筛选，还是应降为软/娱乐？

只要定义或分母不一致，就不能定A级。

### 步骤4：登记转换公式

在JSON `transformation` 中写到可以由另一位维护者复算。例如：

```text
未婚率(age, sex) = 未婚人数(age, sex) / 总人数(age, sex)

不吸烟率(sex) = 1 - 现在吸烟率(sex)

区间身高率 = Φ((upper - μ) / σ) - Φ((lower - μ) / σ)
```

不得写“模型推算”“综合估计”后省略公式。涉及插值、外推、地区缩放或相关性修正时，逐项写入 `adjustments`。

### 步骤5：评定等级和用途

- 相同定义、相同分母的直接数：A。
- 补集、互斥类别求和、单位换算等简单转换：B（原始数仍可另列A）。
- 分布拟合、跨分母换算、多源拼接：C。
- 主观/娱乐、证据与产品定义不相符：D。

给出 `modelUse`：`direct | anchor | calibration | excluded`。D级必须为 `excluded`；C级若会显著影响人数，必须有保守/基准/乐观三组和敏感性测试。

### 步骤6：更新模型，不重复扣减

先把条目放入相关簇：

- 基础人口。
- 经济社会。
- 健康行为。
- 软匹配。
- 娱乐。

若来源本身已经是联合/条件分布，不要再乘其组成项的无条件边际率。例如学历条件收入已经进入 `P(income | education)` 后，不再额外乘一次独立收入率。

### 步骤7：校准与守恒检查

至少检查：

- 18—50岁每个单岁均为正数。
- 年龄区间拆分后再合并，误差只来自浮点/舍入。
- 男女合计与总人口基本守恒。
- `population-by-age.json` 恰好33行，年龄连续覆盖18—50、无重复，每行严格满足 `total = male + female`，且逐岁合计与原表5岁组汇总一致。
- 产品提供的未婚、离婚未再婚、丧偶未再婚三类必须互斥；并集等于三者之和且不超过1。公开选项不含“有配偶”，所以三项全选不会接近1；空选表示不限婚史（也包含有配偶者），因子严格等于1。
- 学历四类严格互斥，多选按并集；“本科”只取本科精确类别，“本科及以上”只能由本科、硕士、博士显式多选得到。
- 学历机器表恰好33行、连续覆盖18—50岁；33个单岁行的495格逐格一致，6个完整五岁组的90个汇总格由单岁回算为0误差，共核验585格。
- 四个学历精确类别总计为190,366,735人，占同口径18—50岁人口29.215208%；单独启用学历时应逐岁×性别精确复现源表。
- 学历与婚史、身高、烟酒同时启用时进入同一逐岁Fréchet联合链；中心条件独立值只作为透明情景，不得描述成观测到的现实独立性。
- 城市人口不再额外乘城镇化率。
- 家庭资产/住房/车辆不当作个人独立率连乘。
- 所有概率在 `[0,1]`，无NaN/Infinity/负人数。

### 步骤8：生成影响报告

对代表性场景输出旧/新：

- 基础池。
- 基准、乐观、保守人数。
- 最大影响条件。
- 每个因子/簇的变化。
- 置信等级变化。
- 变化原因（新数据、修正分母、相关性、定义变化）。

结果变化超过20%需在CHANGELOG和场景对比报告中单列。改变分类（硬→软/娱乐）属于模型语义变更，必须提升 `modelVersion`，不能只改 `dataVersion`。

## 4. 版本规则

### `dataVersion`

格式：`YYYY.MM.DD[.revision]`。同一天需要发布可区分、可回滚的数据修订时追加正整数修订号，例如 `2026.08.14.1`；首个当日版本可以不带修订号。以下情况更新：

- 新发布数据替换旧锚点。
- 新增/删除来源。
- 修复原表抄录、单位、分母或URL。
- 调整可信等级或数据局限说明。

### `modelVersion`

语义版本：

- PATCH：不改变产品语义的小修，例如数值精度和边界保护。
- MINOR：增加维度或替换可兼容算法，典型结果变化受控。
- MAJOR：硬/软/娱乐分类改变、相关簇重建、基础池口径改变或结果含义改变。

注册表顶层和每条entry的版本必须一致；运行时结果、分享图和影响报告都显示版本。

## 5. 机器可读登记表字段

每条entry必需字段：

```text
id

definition

applicablePopulation
geography

sexBasis
dataYear
publisher
sourceTitle

transformation

limitations[]

```

允许同一 `dimensionId` 多条证据，例如身高有体育总局年龄均值、卫健委宏观校准和C级分布假设。`id` 必须唯一且稳定，建议：

```text
evidence.<dimensionId>.<short-source>
```

## 6. 自动质量检查

注册表检查至少覆盖：

- JSON可解析。
- `id` 无重复。
- 所有URL为绝对HTTPS（确有必要的官方HTTP例外需说明）。
- `retrievedAt` 是合法日期且不晚于构建日。
- 顶层/条目 `dataVersion` 和 `modelVersion` 一致。
- `grade=D` 必须 `modelUse=excluded`。
- `modelUse=direct` 不允许D级。
- `classification=entertainment` 不允许进入人口估算。
- `estimate` 的share在非空时落在 `[0,1]`；特殊非概率参数应使用专用unit，或在限制里明确。
- 硬/相关硬维度至少一条非D证据；否则构建失败或自动降级为软。
- UI显示的来源ID都存在；没有悬空引用。

非比例参数必须使用专用unit。当前已支持 `vehicles_per_100_households` 和 `log_scale_sd`；不允许为绕过 `share` 的 `[0,1]` 门禁而把它们标成比例。

## 7. URL与版权维护

- 链接到原始页面/PDF/机器表，不把文章全文复制进仓库。
- 文档只摘录支持模型所需的短数值和口径，遵守版权限制。
- 每季度用HEAD/GET检查状态码与内容标题；仅有200但被重定向首页也算失效。
- 官方站改版时保留旧URL和新URL变更记录。
- 对必须登录/付费的资料，不上传原文；记录DOI/书目信息，并用公开摘要可核实的范围。
