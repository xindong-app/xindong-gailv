## 2. 冻结的结果语义

1. 主结果只回答中国大陆 18–50 岁全国或所选城市常住人口中，满足**已可靠量化硬条件**的人数范围。
2. 未选条件不参与筛选；婚史空选表示不限，包含有配偶等所有婚史状态。
3. 证据不足的敏感硬条件保留用户意图，但不编造发生率；主数字标为 `upper_bound`，逐项返回未计入条件。
4. 无可靠城市常住人口锚点时返回 `unavailable`，不是 0，也不输出历史约数。
5. 严格区分逻辑 0、正数小于 1、数值下溢和不可估算。
6. 范围是逐年龄层传播的敏感性边界，不是抽样置信区间。
7. 关系情境是主人口之外的第二层；取向相容、当前单身、关系意愿采用低可信宽情境，绝不叫爱情或相遇概率。

## 3. 已完成的算法与数据修复

### 3.1 可量化政策与结果状态

- `population.status` 支持 `estimated / upper_bound / unavailable`。
- `coverage` 分开返回已计入与未量化硬条件；`hardRequirementIds` 有严格运行时 schema，非法、未选择和娱乐维度会返回稳定错误。
- 收入、资产、住房、车辆、体型、学历、疾病等缺少同口径目标人口参数时保持 `do_not_apply`，不再用宏观均值或家庭指标伪造个人发生率。
- 无锚点城市不进入数值路径；只要所选城市集合含一个不支持城市，完整集合即不可估算，不偷偷只算其余城市。

### 3.2 人口与城市基数

- 全国基础池使用七普 2020 年 18–50 岁逐单岁、分性别人口，33 行合计 `651,601,516`，逐行满足男女守恒。
- 城市结构缩放分母使用七普大陆总人口 `1,411,778,724`；2025 年全国总人口只作宏观校准，不再与 2020 单岁分子混算。
- 46 个可选城市全部显式登记：20 个有官方常住人口锚点，26 个明确不可量化。
- 城市只有总量锚点而没有同口径年龄、性别、婚史结构，故运行结果维持 C 级宽情景，不冒充城市直接观测。

### 3.3 单调性、可加性与范围

- 计算改为逐单岁、逐城市分层求和，消除年龄中点和先平均城市参数再过非线性函数造成的不守恒。
- 婚史、身高、吸烟和饮酒作为同一年龄层边际；基准采用透明独立情景，范围采用 Fréchet 联合界，不宣称真实独立。
- 城市结构、婚史映射、身高参数端点、吸烟结构和饮酒 raking 端点逐层传播；删除“每多一个 C 级条件就机械乘 0.7/1.3”和末端重复扩宽。
- 乐观值允许高于城市参考年龄结构，但不超过所选行政区全部常住人口 `scopeCeiling`。
- 反例门禁覆盖增加硬条件不得增加人数、扩大 OR 集合不得减少人数、年龄分段和互不重叠城市并集可加、范围有序且受物理上限约束。独立枚举复核了 324 个范围组合和 1,152 个年龄可加组合，未发现失败。

### 3.4 四类关系情境

- 独立 API 支持男找女、女找男、男找男和女找女，并要求同时提供本人和目标统计性别。
- 取向相容、当前单身、关系意愿分别返回来源、范围和状态；无数据时用 `NA`，不把“没有证据”提升成 D。
- 使用对数空间计算极小正数，逐边界区分显式零、主人口逻辑零、主人口敏感性边界零和数值下溢。
- 全部比例为 1 时精确守恒主人口；其他结果夹取到主人口数学上限。
- 关系来源、版本、检索日期、HTTPS、文档路径、来源引用和情境范围已经接入 `validate:model`。

### 3.5 证据与生产包

- 完整证据登记共 65 条：A=38、B=6、C=10、D=11，17 条排除；运行时投影与完整登记逐项同步校验。
- 生产端只打包可追溯展示所需的证据投影，完整定义和严格校验保留在数据文件、脚本和测试中；没有通过放宽预算掩盖体积问题。
- 生产 JS 为 141.22 kB gzip（产物扫描口径 137.0 KiB），低于 150 KiB 门槛。

## 5. Kimi 前端待办（本轮只审不改）

### P0：分享默认泄露反向自评派生分

默认 `showEntertainment=true`；只要用户填写反向自评，Share DTO 就加入 `scores.bidirectional`，图片和文字会公开受个人自评影响的派生分。隐私说明却明确承诺软契合度与双向命中分完全不进入分享。现有测试只排查旧字段名，形成假通过。

**验收要求**：从分享 DTO、文字和 Canvas 完全移除该派生分，或重新设计独立且默认关闭的明确授权；按当前隐私承诺应优先直接移除。测试必须断言真实键 `bidirectional` 和真实输出文案。

### P1：v3 结果契约尚未接入

- `Home` 仍只调用 `computeModel(selection)`，没有让用户把疾病、生育意愿等已选项声明成硬条件并传入 `hardRequirementIds`。
- 结果页没有联合消费 `population.status`、`zeroMeaning`、`resolutionExceeded` 和 `coverage.unquantifiedHardConditions`；`unavailable`、`upper_bound + <1` 等组合态不能被可靠区分。
- 无锚点城市的占位 0 在结果、分享和趣味漏斗中仍可能被渲染成“低于 1 人 / 神话级 / 亿里挑一”，把不可估算误成人数极少。
- 关系情境 API 尚无产品入口，因此男男、女女及两类异性组合目前只在算法 API 可用。
- 漏斗把未量化的学历、经济、体型等维度画成“淘汰 0%”，容易被理解为现实中没有筛选作用。

**验收要求**：为 `estimated / upper_bound / unavailable` 建立独立状态组件；逐项列出未量化硬条件；不可用时禁用人数、稀有度、漏斗和分享趣味推导；增加自愿填写的本人统计性别与关系情境入口。

### P1：一键放宽接线错误

引擎建议“放宽年龄”表示改为 18–50；页面却复用普通删除函数，把年龄恢复为默认 26–34。默认场景本来就是 26–34，因此点击后数值完全不变。

**验收要求**：引擎边际复算和 UI 操作共用一个 `applyRelaxation`；回归应同时验证年龄变为 18–50、人数变为建议值以及撤销恢复原年龄。

### P1：分享还有两条旁路

- 隐藏地区后，趣味人物仍按原城市选择，可能用“胡同大爷”“龙井茶艺师”等反推出地区。
- 未公开敏感条件可能以“神秘条件 + 精确淘汰比例”泄露其存在和影响强度。

**验收要求**：隐藏地区时只使用全国通用人物；趣味总评必须只用已公开、已量化条件重算，否则整段省略。

### P1：第三方字体与隐私声明冲突

生产 `index.html` 会请求 `fonts.googleapis.com` 和 `fonts.gstatic.com`，与“核心流程离线、无第三方字体”的隐私承诺相反，也使离线与生产网络两个 E2E 失败。

**验收要求**：移除远程字体，改系统字体或合规自托管；网络测试不得靠放行 Google 域名通过。

### P1：概率化与羞辱性文案

现有趣味层仍将人口比例称为“遇见概率 / 彩票概率”，并包含“穷是我的错吗”“投胎”“身材管理大失败”“植发分期”等经济或身体羞辱文案。

**验收要求**：统一改为中性的人群比例、数据覆盖和模型边界表达；不得把收入、身体、疾病或婚史作为嘲讽对象。

### P1：1024 px 横向溢出

维度库在 1024 px 实测 `clientWidth=1024`、`scrollWidth=1054`，其余 320/360/390/768/1440 和 720 px 的 200% 等效用例通过。

**验收要求**：修复具体超宽元素后，六档宽度与 200% 等效用例全部无横向滚动。

### E2E 状态说明

当前五个失败为：Google Fonts 导致两个网络/离线用例失败、1024 px 溢出、一键放宽真实接线错误，以及一个对“上限 + 低分辨率”组合态使用旧精确短文案的断言。最后一项的直接失败原因是测试陈旧，但它同时证明 UI 尚未完整呈现组合状态；应在前端接入 v3 后改为断言结构化状态，而不是简单删除测试。

## 6. 已知模型局限

- 全国年龄结构仍以 2020 七普为基础；更新年份只能在取得同口径逐岁表后替换。
- 城市只掌握总量锚点，结构外推保持 C 级；26 个无锚点城市明确不可用。
- 婚史使用性别×五岁组映射，身高离散度、烟酒联合结构仍缺同分母微观表。
- 同性与异性关系第二层属于 D/NA 宽情境，不是官方目标人数、关系成功率或置信区间。
- 收入、财富、住房、车辆、疾病等未量化硬条件会让主数字成为上限；这比伪精确扣减更宽，但更诚实。

## 7. 解封条件

只有在第 5 节问题由前端维护者修复、隐私测试不再假通过、v3 契约和关系层完成 UI 接入、完整 `npm.cmd run check` 通过后，整机裁决才能从 BLOCK 改为 ACCEPT。算法/数据层本身已可作为稳定契约交给前端集成，不需要为了让界面“看起来有结果”重新引入无证据概率。
